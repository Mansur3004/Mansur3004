# TECH_INTERNET_FUNNEL — MISREP-4455

Актуальный прототип: [build_internet_funnel_v4.sql](sql/build_internet_funnel_v4.sql).
Упрощён по замечаниям от 05.11.2026: внутренний ETL TQS удалён из TIF.
Итог: `&db_sbx.man_prt_tif_tech_internet_funnel`, 19 согласованных атрибутов.
[Назначение шагов](docs/prototype_v4_steps.txt),
[что заменено относительно прежнего скрипта](docs/v4_vs_screenshots.txt),
[атрибуты](docs/attributes_catalog.txt).

Анкетные RK, ID, дата и продукт берутся из **готовой TQS**. По её истории
статусов рассчитывается верификация; затем флаг присоединяется к текущей
строке TQS. Очистка RAW, определение продукта и построение интервалов TQS
в прототипе не повторяются.

Для КН/КК используется цепочка:
`TQS.questionnaire_id → questionnaire_x_intention.questionnaire_id/application_num
→ BDM.APPLICATION → TAS.parent_application_rk`.
Из intention читаются только два поля: ID анкеты и номер заявки. Совпадать
должны BDM `application_rk/src_cd` и TAS `parent_application_rk/parent_src_cd`.
Авто соединяется напрямую: `TQS.questionnaire_id = TAS.application_id`.

TAS хранит последнее состояние заявки, её флаги/даты переносятся без пересчёта.
Сначала собирается анкетная часть через `LEFT JOIN`, затем через `NOT EXISTS`
добавляются только оставшиеся заявки. Отсутствующие RK равны `-1`; при связи
верификация `true`, без анкеты — `NULL`. Уровень 35 переносится из собственного
поля TAS; без заявки/значения — `NULL`. Для уровня 25 сохраняется запасное
значение продукта из TQS.

База покрытия теперь определяется TQS, включая анкеты без записи в intention
и без номера заявки. Старые счётчики КН/КК на базе восстановленной RAW-цепочки
с этой выборкой напрямую не сравниваются. Номера сохраняются все; сворачиваются
только одинаковые пары ID/номер и одинаковые ключи связей, не атрибуты TAS.

[Проверки](sql/check_internet_funnel.sql) выполняются отдельными SELECT,
без создания дополнительных таблиц. Покрытие считается отдельно по продуктам.
Для вопросов о повторах и гарантии одного номера на анкету добавлены
[диагностика кратности](sql/diagnose_join_multiplicity.sql) и
[разбор исходной логики TQS](docs/join_multiplicity_review.txt).
Группировки отношений пока не заменяются произвольным выбором одной строки:
сначала нужно отличить повтор пары от нескольких номеров и нескольких дочерних заявок.

Регламент: начальное наполнение с 01.01.2025, далее пересчёт с начала прошлого
квартала. `P_BEGIN_DATE` задаётся ETL/SQL-клиентом, `p_report_timestamp` — единый
момент загрузки. Прототип пересоздаёт выборку в `sbx_pre_orb_fd`; сохранение
данных вне окна и загрузку целевой витрины `dm_pik_fd_cdmr` обеспечивает ETL.

Локальная проверка:

```sh
PYTHONDONTWRITEBYTECODE=1 /workspace/.venvs/qas/bin/python tests/validate_prototype_v4.py
```

Тестовая intention содержит ровно два столбца. Тесты проверяют готовую TQS,
все статусы верификации, отсутствие номера/RAW-записи, несколько номеров,
связи через родителя, авто, остаток TAS, продукты и 19 итоговых полей.
Используются DuckDB и PostgreSQL-разбор pglast. Банковская БД/Greenplum здесь
не запускались. Предыдущие варианты доступны в истории Git.
