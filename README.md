# TECH_INTERNET_FUNNEL — MISREP-4455

Текущий прототип: [build_internet_funnel_v4.sql](sql/build_internet_funnel_v4.sql).
Результат: `&db_sbx.man_prt_tif_tech_internet_funnel`, 19 атрибутов.
[Шаги и изменения по ФТ](docs/prototype_v4_steps.txt).
[Атрибуты источников и всех промежуточных таблиц](docs/attributes_catalog.txt).

В V4 для КН/КК действует только связь
`BDM.APPLICATION.application_rk = TAS.parent_application_rk`
с `BDM.APPLICATION.src_cd = TAS.parent_src_cd`.
Авто соединяется по `questionnaire_id = application_id`.
Сначала собираются анкеты через `LEFT JOIN`, затем через `NOT EXISTS`
добавляются только заявки TAS, ещё не попавшие в анкетную часть.
`DISTINCT` оставлен в скопированной очистке RAW; дальше сворачиваются
ключи номеров/связей, строки TAS и итоговые атрибуты не дедуплицируются.
Отсутствующие RK равны `-1`; при связи флаг верификации равен `true`.

Уточнённая обработка состояний и продуктов:

- TAS хранит только последнее состояние заявки: изменения переписывают строку.
  Временное соединение с TAS и выбор по `processed_dttm` не требуются.
- Для авто сначала рассчитывается верификация по всей истории TQS, затем
  для связи выбирается текущий `questionnaire_id` по `effective_to_dttm = max_date`.
- `level25` берётся из TAS, при отсутствии — из анкеты.
  `level35` переносится из собственного поля TAS. Без заявки или без значения
  в TAS остаётся `NULL`, как в ФТ 1.4. Равенство уровней не задаётся.

Регламент: начальное наполнение с 01.01.2025, затем ежедневный пересчёт с начала
прошлого квартала. `P_BEGIN_DATE` задаёт пересчитываемую выборку, `p_report_timestamp`
— единый момент загрузки. Макросы подставляются клиентом/ETL; комментарии
не создают их. Это расчётный прототип в `sbx_pre_orb_fd`, а не загрузчик целевой
витрины `dm_pik_fd_cdmr`: сохранение данных вне окна обеспечивает целевой ETL.

[Проверки](sql/check_internet_funnel.sql) — отдельные SELECT без новых таблиц.
Покрытие считается отдельно по КН, КК и авто; у анкет и заявок свои знаменатели.
Повторы ключа TAS сначала исследуются, а не устраняются через `DISTINCT`.
Полного исходного ETL TAS в репозитории нет; используются предоставленные поля.

Проверка локально:

```sh
PYTHONDONTWRITEBYTECODE=1 /workspace/.venvs/qas/bin/python tests/validate_prototype_v4.py
```

Тесты используют синтетические данные DuckDB и PostgreSQL-разбор `pglast`.
На банковской БД/Greenplum скрипт не запускался. Устаревшие версии SQL,
диагностики и тесты удалены из рабочей версии; они доступны в истории Git.
