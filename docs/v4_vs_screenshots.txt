============================================
Исходная сторона — скрипт из последнего сообщения пользователя, строки 1–923.
Новая сторона — sql/build_internet_funnel_v4.sql, комментированная версия.

Этой доработкой изменены только комментарии и описание. SQL-логика V4
сравнена по синтаксическим деревьям до/после: все 38 операторов совпадают.

ТЕХНИЧЕСКИЕ ПРАВКИ, КОТОРЫЕ ЕСТЬ И В НОВОМ ФАЙЛЕ
------------------------------------------------
1. man_prt_tif_tif_tqs_* приведено к одному man_prt_tif_tqs_* во всех CREATE/FROM.
   На скриншотах старые CREATE общей истории (402) и её чтение (484) расходятся по имени.
   В новой подготовке статусов единые имена используются последовательно.
2. В старом блоке 704–728 используются q.q_* и недоступный алиас m в проекции продукта.
   V4 читает корректные поля своей отдельной анкетной базы; этого блока больше нет.
3. В старых 733–734 после NULL внутри CAST стоят лишние имена полей.
   Новый 3.2 явно выдаёт NULL нужного типа для даты/флага отсутствующей анкеты.
4. Старые 851–852 и 885/907 читают prt_auto_*/prt_kn_kk_fin без созданного префикса.
   В V4 FROM/JOIN используют реально создаваемые man_prt_tif_*.
5. В старой строке 576 используется равенство для списка источников КК.
   Этот старый фильтр удалён вместе со схемой маппинга; новый источник сопоставляется в 1.12.

СТАТУСНЫЙ ФЛАГ И ВЕРСИИ
----------------------
TAS хранит последнее состояние, временной JOIN не нужен. История TQS нужна
для MAX флага, поэтому фильтр текущей версии применяется только к отображению ID.
Наличие связанной заявки означает true. Заявка без анкеты получает NULL флаг;
анкета без заявки сохраняет исторический true/false. Несколько исторических
строк одного questionnaire_rk не объявляются дублем, ключ TQS включает effective_from_dttm.
