ЧТО ЗАМЕНЕНО ПО ПОСЛЕДНИМ ЗАМЕЧАНИЯМ ОТ 05.11.2026
=================================================
Текущий файл: sql/build_internet_funnel_v4.sql.
Эта правка заменяет прежние пояснения о необходимости копировать ETL TQS.
Старые номера строк со скриншотов больше не служат картой текущей структуры.

ПРЕЖНЯЯ ЧАСТЬ                         -> ТЕКУЩАЯ ЧАСТЬ
-----------------------------------------------------
Очистка RAW и ROW_NUMBER               -> УДАЛЕНЫ из TIF.
CASE продуктов/названий/приоритетов     -> УДАЛЕНЫ: продукт/статус уже есть в TQS.
Временные сдвиги LAG и расчёт LEAD       -> УДАЛЕНЫ: интервалы TQS уже рассчитаны.
Получение RK через восстановленную TQS -> УДАЛЕНО: RK напрямую из готовой TQS.
Раздельные флаги КН/КК и авто           -> 1.1: один MAX по истории готовой TQS.
Анкетные дата/ID/продукт из RAW-цепочки -> 1.2: напрямую из текущей строки TQS.
Вся RAW-цепочка ради application_num   -> 1.3: только пары questionnaire_id/application_num.
Старый переход через номера к BDM      -> 1.4: те же номера из двухколоночного моста.
Два входа TAS КН/КК и авто              -> 1.5: один снимок TAS для трёх продуктов.
Раздельные совпадения двух веток        -> 2.1: родительский путь КН/КК и ID-путь авто.
Раздельные анкетные части + UNION       -> 2.2: единый LEFT JOIN от готовых анкет.
Общий остаток TAS и финал               -> 2.3/2.4: прежний принцип NOT EXISTS + UNION ALL.

СОХРАНЁННЫЕ БИЗНЕС-ПРАВИЛА
--------------------------
КН/КК: BDM.application_rk = TAS.parent_application_rk;
       BDM.src_cd = TAS.parent_src_cd.
Авто: TQS.questionnaire_id = TAS.application_id.
Флаг по историческим статусам; при найденной заявке true, без анкеты NULL.
Отсутствующие RK -1. Собственные даты/флаги и level35 TAS сохраняются.
При пустом TAS.level25 продукт дополняется из TQS. Финал — 19 полей.

p_test_*, p_min_dttm, p_rds_report_dt_date,

ЧТО МОЖЕТ ИЗМЕНИТЬСЯ В РЕЗУЛЬТАТАХ
---------------------------------
Все отобранные текущие анкеты TQS участвуют в базе, даже без строки intention.
Флаг и дата не зависят от статусов/дат RAW. Из intention допускаются все пары
ID/номер для этих анкет, без прежнего отбора по RAW-статусу и приоритетам.
Поэтому покрытие и количества нужно пересчитать на новой базе по каждому продукту.
