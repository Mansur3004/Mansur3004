-------------------
1. Готовый questionnaire_rk берётся из TECH_QUESTIONNAIRE_STATUS, не TQXC.
2. В трёх итоговых RK нет NULL. Отсутствие сущности обозначается -1.

4. Анкета без заявки сохраняет MAX(CASE) по согласованным статусам её продукта.
   Для заявки без анкеты флаг анкеты, дата анкеты равны NULL.

   COALESCE(TAS.level25_product_bp_nm, продукт анкеты).

7. Объект целевой реализации: dm_pik_fd_cdmr.TECH_INTERNET_FUNNEL;
   ежедневно после обновления источников, полный перерасчёт с 01.01.2025;
   результат без истории версий. Рабочий прототип создаёт таблицы в &db_sbx.

В последнем загруженном DOCX остались две старые формулировки: пункт 1.2,
строка 2 запрещает менять флаг из-за связи, а пункт 1.4 для level35 оставляет

ШАГ 1.9: строки 578–615. Готовая TAS КН/КК
----------------------------------------
Строки 588 и 597:

  nullif(t.application_rk, -1)        -> coalesce(t.application_rk, -1)
Исходный -1 сохраняется, возможный NULL становится -1.
Добавить в WHERE условие наличия хотя бы одного реального заявочного ключа:

     or coalesce(t.application_rk, -1) <> -1)

Это следует из критерия ФТ: строка не может состоять из трёх отсутствующих RK.
Отбор источников/дат TAS оставлен как в текущем скрипте. Его объёмы и
соотношение источников с продуктами нужно анализировать отдельно при
проверке сходимости; эта правка не заменяет такой анализ.
